# Gmail SMTP на Node.js VM

LifeSync поддерживает `EMAIL_PROVIDER=smtp` для писем подтверждения email, восстановления пароля и остальных писем авторизации. Можно использовать обычный личный Gmail-аккаунт: отдельный платный почтовый домен и Resend не требуются. Отправка выполняется на VM независимо от локального компьютера.

SMTP-провайдер использует Nodemailer и Node.js TCP/TLS. Он предназначен для Node.js сервера на VM; этот SMTP-транспорт не поддерживается конфигурацией Cloudflare Workers LifeSync. Для Workers сохраняется HTTP-провайдер Resend.

## Настройка Gmail

1. В [Google Account → Security](https://myaccount.google.com/security) включите двухэтапную аутентификацию.
2. Откройте [App passwords](https://myaccount.google.com/apppasswords), создайте отдельный пароль приложения с именем LifeSync и сохраните его только в серверной конфигурации. В `SMTP_PASSWORD` используйте пароль приложения без пробелов, а не обычный пароль Google.
3. Укажите адрес этого аккаунта в `SMTP_USER` и `EMAIL_FROM`. Для отправителя разрешено отображаемое имя: `LifeSync <your.account@gmail.com>`.

По [официальной инструкции Google](https://support.google.com/accounts/answer/185833?hl=en) пароли приложений требуют 2FA. Опция может отсутствовать при Advanced Protection, 2FA только через ключи безопасности или ограничениях организационного аккаунта. После смены основного пароля Google существующие App Passwords отзываются; создайте новый и обновите серверный секрет.

## Серверные поля

| Поле | Значение для Gmail |
| --- | --- |
| `EMAIL_PROVIDER` | `smtp` |
| `EMAIL_FROM` | `LifeSync <your.account@gmail.com>` |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_SECURE` | `true` |
| `SMTP_USER` | `your.account@gmail.com` |
| `SMTP_PASSWORD` | Созданный пароль приложения, секрет |

Для порта `587` задайте **оба** поля: `SMTP_PORT=587`, `SMTP_SECURE=false`. В этом режиме приложение обязательно требует STARTTLS и откажет при невозможности шифрования. Порт 465 требует `true`; порт 587 требует `false`. Режимы и флаг `requireTLS` описаны в [документации Nodemailer](https://nodemailer.com/smtp).

VM должна разрешать исходящие соединения к Gmail на выбранном порту. Входящий SMTP-порт на VM открывать не нужно: LifeSync работает как клиент, а не почтовый сервер. Храните пароль в серверном secret/env-файле с ограниченными правами; не помещайте его в Git, HTML, браузерные переменные, скриншоты или журналы. Если деплой выполняется workflow, передавайте пароль как GitHub Environment secret `SMTP_PASSWORD`.

В production и staging обязательны все SMTP-поля, корректный отправитель и `TURNSTILE_SECRET_KEY`; также сохраняются требования HTTPS и единого origin приложения/авторизации. `RESEND_API_KEY` при выборе SMTP не нужен. Ошибки конфигурации прерывают запуск вместо подмены почты локальным провайдером.

## Проверка и ограничения

После настройки перезапустите Node.js API через ваш механизм развёртывания. Зарегистрируйте тестовую учётную запись и подтвердите письмо, затем проверьте восстановление пароля. Проверяйте и папку Spam. Автоматические локальные тесты подменяют только транспорт и не доказывают успешную отправку через ваш Gmail-аккаунт или доступность сети VM.

Провайдер ограничивает DNS, соединение, приветствие и ожидание данных таймаутами по 15 секунд, проверяет принятие получателя и возвращает безопасную ошибку без SMTP-деталей, пароля и ссылки авторизации. Отправка SMTP не имеет автоматических повторов, чтобы не размножать письма после неоднозначного сетевого сбоя. Принятие SMTP-сервером не гарантирует попадание в Inbox.

Личный Gmail имеет ограничения отправки: [Google указывает лимит порядка 500 писем в день](https://support.google.com/mail/answer/22839?hl=en); блокировки и недоставляемые адреса также могут временно ограничивать отправку. Для небольшой группы 5–10 пользователей обычные письма авторизации укладываются в этот порядок, но Gmail не является безлимитной рассылкой и не гарантирует непрерывную доставку.
